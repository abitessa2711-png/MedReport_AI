# MedReport AI — Bilingual Medical Report Analysis

A working prototype that takes a real lab report image or PDF, runs it through
OCR, structures the extracted test values, checks them against the report's
own reference ranges, and generates a plain-language summary in **English and
Tamil**. No OCR output, test values, or AI text in this app are hardcoded —
everything is driven by whatever is actually on the report you upload.

```
Report Image/PDF
      │  (Tesseract OCR / PDF text layer)
      ▼
Raw OCR text
      │  (regex-based table parser)
      ▼
Structured rows: {test_name, value, unit, reference_range}
      │  (compare value vs. the report's own range)
      ▼
Structured rows + status: Normal / Low / High / Unknown
      │  (LLM, given ONLY this structured JSON — never the image)
      ▼
Bilingual summary (English + Tamil)
      │
      ▼
Dashboard: tables, chart, history
```

**This is an educational/information tool. It does not diagnose disease and
does not recommend medicines or dosages.** Every result screen shows this
disclaimer.

## 1. Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Python | 3.10+ | backend |
| Node.js | 18+ | frontend (Vite) |
| MySQL | 8.0+ | database |
| Tesseract OCR | 5.x | real OCR engine |
| Poppler / PyMuPDF | — | reading PDFs (PyMuPDF is pure-Python, no extra install needed) |

### Install Tesseract OCR

- **macOS:** `brew install tesseract`
- **Ubuntu/Debian:** `sudo apt-get install tesseract-ocr`
- **Windows:** install from the [UB-Mannheim Tesseract build](https://github.com/UB-Mannheim/tesseract/wiki), then set `TESSERACT_CMD` in `.env` to the install path, e.g. `C:\Program Files\Tesseract-OCR\tesseract.exe`.

Verify it works:
```bash
tesseract --version
```

PDF pages are rasterized with **PyMuPDF** (`pip install PyMuPDF`, already in
`requirements.txt`), so no separate Poppler install is required even for
scanned/photographed PDF reports.

## 2. Database setup (MySQL)

```bash
mysql -u root -p -e "CREATE DATABASE medreport_db CHARACTER SET utf8mb4;"
mysql -u root -p -e "CREATE USER 'medreport_user'@'localhost' IDENTIFIED BY 'change_me';"
mysql -u root -p -e "GRANT ALL PRIVILEGES ON medreport_db.* TO 'medreport_user'@'localhost';"

mysql -u medreport_user -p medreport_db < backend/database/schema.sql
```

This creates four tables: `users`, `reports`, `extracted_results`,
`analysis_results` (see `backend/database/schema.sql` for the full DDL and
comments on each column).

## 3. Backend setup

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
# then edit .env:
#   - DB_HOST / DB_USER / DB_PASSWORD / DB_NAME to match step 2
#   - AI_PROVIDER=anthropic (or openai)
#   - ANTHROPIC_API_KEY=sk-ant-...   (or OPENAI_API_KEY=sk-...)
#   - TESSERACT_CMD / POPPLER_PATH only needed on Windows

uvicorn app.main:app --reload --port 8000
```

The API is now live at `http://localhost:8000`. Interactive docs (Swagger UI)
are auto-generated by FastAPI at `http://localhost:8000/docs` — useful for
testing `/upload-report`, `/extract-report`, and `/analyze-report` directly.

### AI provider configuration

The summary-generation step is provider-agnostic. In `backend/.env`:

```
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-xxxxx
ANTHROPIC_MODEL=claude-sonnet-4-6
```

or

```
AI_PROVIDER=openai
OPENAI_API_KEY=sk-xxxxx
OPENAI_MODEL=gpt-4o-mini
```

The AI is only ever given the **structured JSON** built from the OCR'd and
validated test rows (test name, value, unit, reference range, computed
status) — never the raw image — so it can't invent findings that weren't
actually extracted.

## 5. Using the app

1. **Upload** a JPG/PNG/PDF of a real lab report (drag-and-drop or click to
   browse). Optionally enter age/gender.
2. The backend runs **real OCR** (`/extract-report`) and shows every test row
   it found — name, value, unit, reference range, and a computed
   Normal/Low/High/Unknown status.
3. **Correct** any row OCR misread (e.g. a smudged "1O.2" you know is
   "10.2") directly in the table before continuing.
4. Click **Generate bilingual summary** (`/analyze-report`). The corrected,
   structured data is sent to the configured LLM, which returns an
   English + Tamil summary (overall, abnormal findings, normal findings,
   points worth discussing with a doctor).
5. Review the **dashboard**: status counts, the full results table, a bar
   chart of numeric values against their reference ranges, and the bilingual
   summary cards.
6. Every analyzed report is saved; visit **Report history** to reopen it
   later via `GET /reports` / `GET /reports/{id}`.

## 6. API reference

| Method | Path | Purpose |
|---|---|---|
| POST | `/upload-report` | multipart upload (`file`, optional `age`, `gender`) → creates a `reports` row |
| POST | `/extract-report` | `{report_id}` → runs OCR + parsing, stores `extracted_results` |
| POST | `/analyze-report` | `{report_id, age?, gender?, corrections?}` → applies corrections, calls the AI, stores `analysis_results` |
| GET | `/reports` | list of past reports for the history page |
| GET | `/reports/{id}` | full detail (extracted rows + analysis) for one report |

## 7. Error handling

The backend returns meaningful HTTP errors (with a `detail` message the
frontend displays) for:
- unsupported file type / empty or oversized upload
- corrupted image/PDF that Tesseract/PyMuPDF can't open
- OCR producing no readable text at all
- OCR text with no identifiable test rows
- a missing/expired uploaded file on disk
- AI provider not configured, or returning a malformed response

---

## 8. Known limitations of this prototype

- The table parser uses layout heuristics (regex over OCR'd lines). Very
  unusual report layouts may need a manual correction in the review step —
  by design, the app never guesses a reference range that wasn't printed.
- Handwritten values are OCR'd with plain Tesseract, which is weaker on
  handwriting than on printed text; the correction step exists specifically
  for this.
- Authentication/user accounts are out of scope — `users` currently just
  stores optional age/gender per report, not login credentials.
